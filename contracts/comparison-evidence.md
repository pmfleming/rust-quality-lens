# Comparable execution and review evidence

`rqlens review --baseline-review saved-review.json` compares stable full-project finding identities from a prior review snapshot, independently of changed-hunk attribution. Review format is now version 3. Save a review at the intended base revision before changing sources. The command does not automatically check out or execute code from Git history. Unknown/incomplete or differently configured snapshots are incomparable, not empty baselines. Source-anchor identity is stable under line shifts, but not guaranteed across arbitrary semantic refactorings or renames.

Criterion imports preserve point estimates, confidence intervals and sample counts. Comparison requires matching recorded environment/toolchain and at least three samples with valid same-level intervals. Overlapping intervals are `within_noise`; missing provenance/uncertainty is `incomparable`. Nonoverlapping intervals are a conservative comparison heuristic, not a full statistical equivalence test. Policy also respects these states instead of gating on point-estimate differences alone.

External report ingestion remains tool-independent. Policy/SARIF consume only reports with `status: completed`, `confidence.complete: true`, and a producer-supplied `input_fingerprint` matching the current inputs. The fingerprint must come from the run that actually generated the report; ingestion does not fabricate it. Findings require `rule_id`, `message`, and `severity` (`error`, `warning`, `advisory`). IDs are namespaced as `external.<adapter>.<rule>`. Configure those rule IDs in `[policy.rules]` to require/gate the evidence. Missing, stale or incomplete evidence for configured external policies fails as an input error, not a suppressible finding.
